# Toy Math Kernel Contract

This document defines the only math-kernel shape allowed in the public Ontologica OS repository without additional rights-holder review.

The public math kernel is a didactic proof surface. It is intentionally small, synthetic, noncanonical, and candidate-only.

## Purpose

The toy math kernel exists to make the public proof flow understandable:

```text
synthetic tesserae
  -> deterministic toy projection
  -> manifest identity
  -> drift comparison
  -> receipt evidence
  -> hold_for_review
```

It demonstrates the kind of boundary a math layer can provide without revealing the private mathematical kernel.

## Allowed Public Behavior

The toy math kernel may:

- parse synthetic tessera fixtures
- use clearly public demonstration fields
- compute deterministic toy projections
- produce SHA-bound public projection objects
- support toy drift comparison
- emit synthetic receipt evidence
- keep `authority_ceiling` set to `candidate_only`
- keep promotion outcomes at `hold`, `warn`, `deny`, or `hold_for_review`

## Forbidden Public Behavior

The toy math kernel must not include:

- private dimensions
- private field semantics
- real constants, weights, or thresholds
- private ranking or scoring logic
- private tensor layouts
- private correlation logic
- model-routing logic
- production validators
- runtime authority
- durable truth promotion
- real manifests
- real SHA lineage
- real receipts
- private traces

## Current Public Dimensions

The current toy proofing demo uses four public demonstration fields:

- `novelty`
- `risk`
- `coherence`
- `embodiment`

These fields are public placeholders. They are not private field semantics and must not be treated as a private ontology.

## Change Policy

A future change may clarify the toy kernel if it makes the proofing path easier to understand.

A future change must be held for rights-holder review if it makes the toy kernel more capable, reconstructable, reusable, production-like, or private-system-revealing.

## Required Invariants

Every public math-kernel path must preserve these invariants:

```text
authority_ceiling: candidate_only
promotion: hold or hold_for_review
receipt_status: evidence_only
truth_claim: none
private_lineage: none
```

The public repository may explain invariants, but it must not export capability.
